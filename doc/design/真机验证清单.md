# 真机验证清单（2.0.15）

这份清单只做一件事：把「CI 证明不了的东西」在真机上一次性验完，并把结果记下来。

- 上位文档：`doc/design/Tauri迁移验收.md`（§4 未验证项、§4.5 打包、§4.6 启动冒烟）
- 通过标准：下面每一项都填完「结果」列；出现 ❌ 时记下现象与 `app.log` 片段，不要凭印象判断。
- 前置：先拿到 2.0.15 的安装包（`release-status` 分支记录的那次构建，或正式 draft release）。

## 3. 登录与会话（对应 §4 第 6 项）

1. 首启要求重新登录（旧 token 由 Electron `safeStorage` 加密，无法解密）——这是**预期**。
2. 登录成功后重启应用 → 会话恢复，不需要再次登录。
3. Linux：确认系统有 Secret Service（gnome-keyring / kwallet）。**故意停掉它**再启动 → 应用应正常起来、只是要求重新登录（不崩溃）。
4. Windows：凭据出现在「凭据管理器」；macOS：出现在「钥匙串访问」。
5. 退出登录 → 凭据被清除；重启后处于未登录状态。

## 12. 已知的有意差异（出现时不要当 bug）

| 现象 | 原因 |
| --- | --- |
| 首次启动要求重新登录 | 1.x 的 token 由 Electron `safeStorage` 加密，Tauri 用系统钥匙串，无法解密旧值 |
| 删除文件进回收站而不是直接删 | 1.x 就是 `shell.trashItem` 语义，已保留 |
| 文件排序是字典序而不是拼音序 | 无 ICU 依赖，`localeCompare('zh')` 无法逐字复刻（已记录为偏差） |
| Linux 上需要先装 `libwebkit2gtk-4.1` | 不再自带渲染引擎——这是安装包从 95 MB 降到 13 MB 的对价 |
| 可执行文件叫 `huangqi-scifi`（包名 `hq-scifi`） | `mainBinaryName` 保持与 1.x 一致，避免快捷方式/防火墙规则失效 |
| 安装包比 1.x 小很多但 AppImage 只小 30% | AppImage 仍是自包含 rootfs，体积大头在运行时 |

## 13. 出问题时怎么取证据

- 应用日志：Linux `~/.local/share/com.huangqisf.client/app.log`（若未写文件，用启动终端里的 stderr）；Windows `%APPDATA%\com.huangqisf.client\`；macOS `~/Library/Logs/` 或 `log show --predicate 'process == "huangqi-scifi"'`。
- 崩溃：Linux `coredumpctl`；Windows 事件查看器；macOS `~/Library/Logs/DiagnosticReports/`。
- 本地库：`hqsf.db` + `hqsf.db-wal`（**取证据时要一起拷**，只拷 db 会丢 WAL 里的行——这是 SP-4 踩过的坑）。
- 记录格式：现象 + 复现步骤 + 期望 vs 实际 + 日志片段，追加到本文件对应表格的「备注」列。
