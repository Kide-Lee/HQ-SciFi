# 共享层与契约设计

> 本文件是 `doc/design-1.md` 的子系统文档之一，描述跨端共享类型、IPC 契约与 Markdown 转换约定。

## 1. 领域类型

- 跨端业务类型：`ArticleRow`、`PullResult`、`UserSession`、`LocalNode`、`ApiResult`、`ReviewItem`、`CommentItem`、`AppSettings` 等。
- 集中维护，避免重复定义漂移。
- 主进程内部临时字段（如脱敏中间态）不要污染 `shared/types.ts`。

### 目标结构
- `src/shared/domain/`：跨端领域类型。
- `src/shared/contracts/`：IPC 通道名、请求/响应类型。
- `src/shared/markdown/`：frontmatter、数学、楷体等转换能力。

## 2. IPC 契约

### 2.1 通道命名
- 统一使用 `domain:action`，例如 `auth:login`、`docs:list`、`sync:pull`、`read:article`。
- 每个领域一个 handler 文件，`ipc/index.ts` 只做注册。
- 返回统一：成功 `{ok:true, data}`，失败 `{ok:false, error}`。
- 保留 `ping`/`getAppInfo` 为兼容历史接口，后续可迁移到 `system:*`。

### 2.2 契约来源
- preload 与主进程 handler 从同一契约引用。
- 后续可评估是否用 manifest 生成 preload 类型，但至少保持手写契约集中。
- 改契约只改一处，渲染层不直接定义主进程才可见的类型。

### 2.3 需要沉淀的契约清单（AI 执行时补充）
- [ ] 各个 IPC 通道的 Request/Response 类型。
- [ ] 现有 `window.hqsf.*` 方法名与 channel 的对应表。
- [ ] 兼容旧裸值接口（`ping` / `getAppInfo`）的迁移说明。

## 3. Markdown 与前端转换

- frontmatter 解析/序列化。
- 数学公式、楷体等编辑器与预览共用能力。
- 转换逻辑保持纯函数，便于复用与测试。
