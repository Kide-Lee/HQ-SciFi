## 3. 总体设计原则

1. **安全优先**：渲染层运行在 `contextIsolation + sandbox`；token 只存主进程；IPC 白名单；本地路径双防穿越；远端内容白名单净化；外链交系统浏览器。
2. **类型单一来源**：跨端类型集中在共享层，主进程 / preload / 渲染层从同一处 import。
3. **API 适配隔离**：荒启接口的 path/method/字段差异集中在 API 配置与领域适配器。
4. **IPC 契约统一**：成功 `{ok:true, data}`，失败 `{ok:false, error}`。
5. **分层清晰**：渲染层只通过 `window.hqsf.*` 访问主进程；主进程内部按“基础设施 → API 适配器 → 领域服务 → IPC 薄层”组织。
6. **渐进式演进**：用户可见功能以 `产品与UX决策记录.md` 为准，未登记的变更不允许；每个阶段保持 `npm run typecheck` / `npm run build` 通过。

## 4. 系统总体架构

### 4.1 进程与依赖边界

```
┌─────────────────────────────────────────────────────────────┐
│ 渲染进程 (React UI)                                          │
│  app/      根组件、协议门、全局壳                              │
│  features/ 业务视图 + 局部状态 + 取数 actions                  │
│  stores/   跨视图状态，按 feature 划分                         │
│  lib/      纯函数/工具，不依赖 window.hqsf                     │
└───────────────────────────┬─────────────────────────────────┘
                            │ window.hqsf.*（类型化白名单 API）
┌───────────────────────────▼─────────────────────────────────┐
│ 预加载层 (preload)                                           │
│  仅做 channel → 方法映射、事件订阅包装                         │
│  不包含业务逻辑；类型从 shared/contracts 导入                  │
└───────────────────────────┬─────────────────────────────────┘
                            │ IPC
┌───────────────────────────▼─────────────────────────────────┐
│ 主进程                                                        │
│  ipc/         领域 handler 注册 + 统一 ok/fail + sender 校验   │
│  services/    应用服务：编排领域用例，不直接依赖 electron        │
│  adapters/    荒启 API 领域适配器：接口调用、字段规整、响应转换   │
│  infra/       net/fs/db/session/settings/imgcache/updater/window│
│  domain/      纯业务规则：活动期评分隔离、匿名脱敏等             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 主进程总体分层

| 层 | 职责 | 不应包含 |
| --- | --- | --- |
| `bootstrap/` | 启动编排、单实例锁、测试模式、初始化顺序、fail-fast | 业务实现 |
| `window/` | 窗口创建、安全配置、顶栏/外部链接/快捷方式等窗口行为 | 业务规则 |
| `ipc/` | 每个领域一个文件；参数校验、调用 service、包装返回 | 业务计算、API 细节 |
| `services/` | 按用例编排 adapter/fs/db/state | 具体接口路径、具体表结构 |
| `adapters/` | 荒启 API 请求与响应映射；每个业务域独立适配器 | Electron 相关、渲染层概念 |
| `infra/` | 网络请求基础、API 配置、SQLite、本地文件、会话加密、图片缓存、设置、更新器等 | 领域规则 |
| `domain/` | 主进程内部领域类型、纯业务函数、规则 | 外部依赖 |

### 4.3 渲染层总体分层

| 层 | 职责 |
| --- | --- |
| `app/` | 根组件、协议门、应用壳、全局事件/错误入口 |
| `features/<feature>/` | 每个业务功能的视图、局部组件、状态、取数 action |
| `components/` | 通用、跨 feature 的展示组件 |
| `stores/` | 按 feature 划分的 Zustand store；跨 feature 共享的极小全局状态保留 |
| `lib/` | 纯函数与不依赖 `window.hqsf` 的工具 |
| `styles/` | 按主题/组件拆分的样式模块 |

### 4.4 共享层总体设计

- `shared/contracts/`：IPC 通道名、请求/响应类型的唯一来源。
- `shared/domain/`：跨端领域类型（ArticleRow、UserSession、ReviewItem、LocalNode、AppSettings 等）。
- 原则：改契约只改一处；渲染层不直接定义主进程才可见的类型。

## 5. 通用设计约定

### 5.1 IPC 契约

- 通道命名：`domain:action`，例如 `auth:login`、`docs:list`、`sync:pull`、`read:article`。
- 每个领域一个 handler 文件，`ipc/index.ts` 只做注册。
- 返回统一：成功 `{ok:true, data}`，失败 `{ok:false, error}`。
- 保留 `ping`/`getAppInfo` 为兼容历史接口，后续可迁移到 `system:*`。

### 5.2 安全约定

- 窗口：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
- IPC：白名单 API，sender 校验，不暴露通用代理。
- 路径：所有本地文件操作经 `assertInside`（resolve + realpath）防穿越。
- 内容：远端 HTML 白名单净化防 XSS；外部链接交系统浏览器。
- 凭据：safeStorage 加密；Linux 无 keyring 时降级并标记 `insecure`。

### 5.3 错误与诊断

- 主进程启动阶段统一 fail-fast：API 配置、数据库、协议注册、IPC 注册任一失败都弹窗退出并留下日志。
- 所有 IPC 异常统一转 `{ok:false, error}`。
- 渲染层错误状态在 store 中保存，UI 提供错误提示与重试入口。

### 5.4 开发与验证策略

- 每个阶段至少保证：`npm run typecheck` 通过、`npm run build` 通过、关键路径手工验证。
- 测试模式 `dev:test` 与正式模式完全隔离，重构时保持兼容。
- 具体测试/回归方案见 `开发计划（重构）.md`。
