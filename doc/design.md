# 黄芪饮片桌面客户端 — 产品与技术设计

## 概述
本应用为 [荒启科幻](https://www.huangqisf.com/h5/#/) 的电脑客户端，旨在为用户打造 写作-阅读-评审 的一站式解决方案。

核心价值一句话：把荒启科幻的在线写作、投稿与社区阅读能力搬回本地 —— 用本地 Markdown 文件写作，随时同步草稿、一键发布，并在本地直接阅读与评审他人作品。

## 目标与边界
**目标用户**：在荒启科幻上创作与阅读的写作者；习惯本地编辑、需要离线写作与本地存档的用户。

**V1 范围**（本期必须）：
- 登录荒启账号，拉取/同步草稿箱，本地 Markdown 写作，发布/同步到草稿
- 浏览 推荐 / 连载 / 活动 / 作品库 内容并阅读
- 对非用户发表的文章打开评审界面

**V1 不做**（明确边界，防止范围蔓延）：
- 不做账号注册/找回密码等账号体系，全部复用荒启现有账号
- 不做完整的离线内容库（在线内容按需拉取，不整站缓存）
- 不做版本管理、AI 能力（列入「展望」）

## 技术栈
| 层次 | 选型 | 理由 |
| --- | --- | --- |
| 桌面框架 | Electron（最新稳定版） | 跨平台 Win11 / Debian13，Chromium 渲染 |
| 语言 | TypeScript（主进程 + 渲染进程） | 类型安全，AI 生成代码质量高 |
| 前端框架 | React 18+ | 生态最大，Electron 社区示例多 |
| 构建工具 | Vite（electron-vite 脚手架） | 主/预加载/渲染三端统一构建，热更新 |
| 编辑器 | CodeMirror 6 | 轻量、专注源码写作、md 文件直编，Obsidian 同路线 |
| Markdown 渲染 | marked + 代码高亮（prismjs 或 highlight.js） | 轻量，渲染阅读/预览视图 |
| 状态管理 | Zustand | 轻量、无样板代码 |
| 图标 | lucide-react（ISC 许可） | 与项目 MIT 兼容；现代扁平线条风格（24×24、stroke + currentColor，可随主题色着色）；纯本地 SVG 组件 + tree-shaking，适配离线渲染层；官方支持 React 19 |
| 本地索引库 | better-sqlite3 | 存文章元数据/状态索引，正文仍是磁盘 md 文件 |
| 设置存储 | electron-store（JSON） | 字号/字体/主题/目录路径等 |
| 打包 | electron-builder | NSIS（Win）+ deb/AppImage（Linux） |
| 自动更新 | electron-updater | Win 与 AppImage 支持；deb 受限（见「分发」） |
| 凭据加密 | Electron `safeStorage` | 加密保存会话凭据 |

> 注：所有代码完全由 AI 生成，因此选型一律偏向「文档多、模板多、AI 训练充分」的主流方案，避免冷门库。

## 系统架构

### 进程模型
- **主进程**：窗口管理、所有网络请求（经 IPC 暴露给渲染层）、本地文件读写、SQLite 索引、会话凭据加密存取、自动更新。
- **预加载脚本**：通过 `contextBridge` 暴露白名单 IPC API（`window.hqsf.*`），渲染进程不直接接触 Node/文件系统。
- **渲染进程**：全部 UI。开启 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`，设置严格 CSP。

### 网络请求为何放主进程
渲染进程以 `file://`/自定义协议加载，直接 `fetch` 荒启 API 会受 CORS 限制；统一走主进程 `net` 模块可避免跨域问题、集中管理 Cookie/Token 与重试，也便于将来切换代理。

### 目录结构草案
```
hqsf/
├─ src/
│  ├─ main/            # 主进程：窗口、net 请求、文件服务、db、updater
│  ├─ preload/         # contextBridge 白名单 API
│  └─ renderer/        # React 应用
│     ├─ components/   # 布局、侧栏、编辑器、阅读器、评审面板
│     ├─ stores/       # Zustand
│     └─ styles/       # 主题（颜色/字体变量）
├─ resources/          # 图标、默认字体等
├─ electron-builder.yml
└─ doc/                # 文档：设计（design.md）/ API 调查（api-research.md）/ 网站调研（site-overview.md）
```

### 本地存储布局
```
~/文档/荒启科幻/              # 本地存档根目录（可改，见「界面」）
├─ 草稿/                     # 与荒启草稿箱同步的 md 文件
├─ 已发布/                   # 已发布文章快照（可选，V1 仅读远端）
└─ ...
```
- 正文一律为 `.md` 文件，用户可用任意编辑器打开。
- SQLite 数据库存元数据索引（文章 id、远端 id、状态、同步时间、内容哈希），不存正文。
- 文件名即文章标题（不带日期）；重名时追加 `(1)`/`(2)` 后缀避免覆盖。

## 认证与会话
1. 登录方式：优先复用荒启 h5 的登录方式（账号密码/验证码等，**实施前需实测确认**，见「风险」）。
2. 登录成功后，将会话 Cookie/Token 用 `safeStorage` 加密持久化，重启免登录；设置中提供「退出登录」清除凭据。
3. 会话失效（401）时：静默提示重新登录，不丢本地内容。
4. 所有请求携带会话态，请求集中在一个 API client 模块中管理，便于统一处理失效与重试。

## 数据同步（写作流程）
1. **首次登录**：自动从荒启草稿箱下载全部草稿 → 以 md 文件写入本地存档「草稿」目录；后续启动时增量拉取（按远端修改时间）。
2. **本地编辑**：在 CodeMirror 6 中编辑 md 文件，本地即时保存（防抖 + Ctrl+S）。
3. **同步到草稿**：将本地文件内容上传覆盖到荒启草稿箱对应草稿（必要时先询问冲突处理）。
4. **发布**：从本地（或草稿箱）提交发布 → 进入荒启审核流程，状态流转为 待审核 / 已拒绝 / 已发布。
5. **冲突策略**：以「远端修改时间 vs 本地最后同步时间」判断；本地较新则提示「覆盖远端 / 保留远端 / 另存副本」，不做自动合并（V1）。
6. 状态映射：本地文件与 荒启「已发布 / 待审核 / 已拒绝」四态通过 SQLite 索引关联，侧栏按状态分组展示。

- **阅读视图**（对应 推荐/连载/活动/作品库 及 已发布 等）：主区渲染文章正文（marked），顶部展示标题/作者/字数；右侧可展开「评审」面板（见下）。

## 与荒启 API 对接
- 官方无公开 API 文档；已通过接口实测完成调查，**完整结论见 `api-research.md`**。要点如下：
- **基础设施**：基址 `https://api.huangqisf.com/`；`application/x-www-form-urlencoded`；鉴权用 `token` 表单参数（登录后存 `localStorage["token"]`）；响应统一 `{code, msg, data, total}`（`code:1` 成功）；列表通用 `searchParams`(JSON)/`limit`/`page`/`order`，写操作通用 `params`(JSON)。站点配置 `system/app`（key=`QyAPIZKw`）公开可读。
- **认证**：账号密码（`hqUsers/userLogin`）、手机验证码（`phoneLogin`+`SendCode`）、第三方（`apiLogin`：qq/weixin/SINAWEIBO）、扫码（`getScan`/`setScan`/`getScanStatus`）。
- **写作闭环**：草稿/待审核/已发布 统一走 `hqContents/contentsList` + `searchParams={type, authorId}`（`post_draft`=草稿、`waiting`=待审核、`post`=已发布）；保存/发布 `contentsAdd`/`contentsUpdate`（`isDraft` 1/0；正文为 **HTML**，`isMd:0`）；详情 `contentsInfo`（**需登录**）；删除 `contentsDelete`。
- **内容浏览**：文章列表/搜索 `contentsList`（`order`：created/score/views/likes/commentsNum 等；`searchKey` 搜索；匿名可读列表但正文需登录）；精选 `choiceList`；分类/合集/连载 `hqMetas/metasList`（`type=category` 即作品库四分类）；AI模型 `gpt/gptList` 等（需登录）。
- **评审**：官方五维评审体系（点子/文笔/人物/节奏/立意，各含评分与 ≥10 字评语）——列表 `review/reviewList`（公开，已有 1.2 万+ 条）、详情 `reviewInfo`、提交 `addReview`/`editReview`、态度 `attitude`；另含 AI 评审（`isAi`）与任务化评审（`reviewTask` 等）。
- **活动/练笔**：与评审的 `activeid` 关联；投票接口（`vote/*`）当前已停用，活动取数方式实施时确认。
- **实现要求**：接口以「适配层」隔离，后续接口变动只改一处；统一处理分页、错误码、限流（退避重试）；登录态失效（`code:0` + 特定 msg）时引导重新登录。**正文格式适配**：本地 md 存储，同步/发布时 md → HTML 转换（荒启正文为 Quill HTML，需保持标题/段落/引用/图片映射正确）。

## 安全
- 会话凭据：`safeStorage` 加密落盘，绝不明文写入配置文件。
- 渲染层不接触 Node API；文件系统与网络仅经预加载白名单 IPC。
- 窗口启用 CSP；不加载远程脚本；所有外部内容按纯文本/降级渲染处理（防 XSS，尤其评审与评论区）。
- 本地存档目录仅按用户显式选择授权访问。

## 风险与开放问题
1. **正文格式差异（重要）**：荒启正文为 Quill HTML（`isMd:0`），本地 md 需在同步/发布时转换；md 文章（`markdown:1`）存在但当前极少，转换器需经真实账号发布/回拉验证（含图片上传 `upload/full`）。
2. **完整正文需登录**：`contentsInfo` 匿名返回「该文章不存在」，阅读视图必须登录态，影响匿名浏览体验（列表仅 400 字摘要）。
3. **风控与验证**：发布在 `verifyLevel>1` 时需验证码；含「内容涉及违规」拦截；自动化访问可能触发限流/封禁，需控制频率并做退避。
4. **活动取数未明**：投票接口（`vote/*`）已停用，练笔活动（`activeid`）列表取数方式实施时确认。
5. **同步冲突**：V1 不自动合并，多端编辑场景体验有限，列入后续版本。
6. **deb 更新**：无法自动更新，只能手动下载，需在界面明示。
7. **接口无文档**：虽有完整调查（`api-research.md`），但接口变动无版本契约，适配层需集中隔离以降低变更影响。

### v0.0.2 样式改进交付记录（2026-08-08，CDP 真机验证 PASS）

- **全局**：任意界面 Ctrl+F12 打开/收起开发者工具（主进程 `before-input-event`，打包后同样可用）。
- **左栏**：推荐/连载/活动顶层点击显示对应栏目首页（推荐=置顶文章+最新发布流；连载=推荐合集/推荐连载；活动=近期活动）；活动按钮红点显示未完成评审任务数；活动树可展开，子项为该活动文章（按标题拼音序，懒加载），正在阅读的文章高亮，待评审/已评审文章带徽章；「进行中」（activeStatus=1）/「评审中」（activeStatus=-1）活动带状态徽章（字段 2026-08-08 实测，见 api-research.md §7）。
- **排序**：新增「按字数」（接口不支持 size，客户端本地排序）；所有排序共用一个 ↑/↓ 方向切换（`order=-field` 为升序，2026-08-08 实测）；评分/点赞/评论/阅读相同的文章排名相同（竞赛式跳号 1,2,2,4，名次与展示方向无关）。
- **评分榜隔离**：进行中/评审中活动的文章列表隐藏「评分榜」排序、不显示评分与排名。
- **评审栏**：正文与评审栏可拖动分栏（默认 1:2，localStorage 持久化）；评审栏字号与正文一致；「我的评审/所有评审」双视图，已评审可随时编辑（editReview，提交后提示等待审核——review 条目无审核状态字段，兜底文案）；表单实时显示五维平均分预示；编辑框随内容自动增高且不显示滚动条、不可手动调高；所有评审按时间/评分/开心/有用/认真排序+倒序；评审条目显示评者头像；评审分数字体颜色与文章评分同规则（scoreColor）。
- **接口实测结论**（2026-08-08）：`order=-field` 反方向；`order=size` 不受支持；`reviewList` order 支持 created/score/joy/helpful/earnest；活动 `activeStatus` 1/-1/0；置顶取数 `contentsList searchParams={istop:1}`；review 条目含 uid/avatar 但无审核状态字段。
